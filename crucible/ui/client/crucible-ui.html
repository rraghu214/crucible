What is an apply probe?
The apply probe performs a real end-to-end test: it pushes a trivial change to perftest_sandbox, confirms the target restarts and passes its readiness probe, reads the property back, then reverts. It exercises deploy → verify → revert exactly as a campaign will.

The target service will restart once. Run this before the first campaign on any new environment.
Manual overrides
If deploy or restart is not automated, declare it here. The campaign will block with instructions when a manual step is reached and record it on the manifest.

Benchmarks
Read from the task set, the captured fixtures and the replay results on disk

    

  

  

    🧪
    
Replay separates diagnosis quality from luck. Each fixture is a metric snapshot captured from a real PerfLab state with its true cause recorded first. The model diagnoses it without running anything live, and the scorer grades it with no model call. Whether a fix worked needs a live campaign, so the diagnosis quadrant (CORRECT, LUCKY, UNLUCKY, WRONG) stays "not yet measured" until one is scored. Re-run with crucible bench; the write-up is docs/BENCHMARK_REPLAY_RESULTS.md.

Safety
Guardrails
What the AI can and cannot do — enforced at the platform level, not just convention

  

  

    🛡️
    
"Always enforced" rules cannot be turned off — each one exists because removing it caused a specific failure during the feasibility spike. The most important table is the profile's tunable properties, at the bottom: the AI can only change what is listed there, with values inside the stated bounds.

    
  

  

    
Core protections
These cannot be disabled — they exist because disabling them reintroduces a specific past failure

    

      
SLA is read-only
The AI cannot raise its own goalposts. The p99 ceiling and error budget you set are locked for the lifetime of the run. Enforced as Policy memory and a protected file path — weakening either independently defeats both.

      Always enforced
    

    

      
Load profile is read-only
Fewer users is not a fix. Reducing load to hit the SLA destroys comparability across runs.

      Always enforced
    

    

      
Writes only to perftest_sandbox
Crucible never writes to main, master, develop, trunk, release/*, hotfix/* or the base branch. Checked when the profile loads, not just at push time.

      Always enforced
    

    

      
No cross-provider failover
Model is pinned per campaign. A campaign whose experiments were diagnosed by different models is not internally comparable. CRUCIBLE_GATEWAY_FALLBACK_PROVIDERS stays empty.

      Always enforced
    

    

      
No force-push
Reverting means deploying an earlier commit, never rewriting history. Force-push would destroy the experiment history that every manifest depends on.

      Always enforced
    

  

  

    
Where the adjustable limits are set
Read-only here, so this page never shows a switch that does nothing

    
Human approval before every change
Set by the mode chosen in New Test Run: Semi-Automated asks, Fully Automated is pre-approved within the profile's bounds, Advisory applies nothing.

    
Revert on a change that is not better
Always on. A change measured WORSE or INCONCLUSIVE against the noise floor is reverted and the last good commit redeployed.

    
Stop on host CPU steal
The threshold is per environment, in config/slo.yaml: default 5%, 10% on Oracle free tier (DESIGN.md §6).

    
Experiments, cost and wall clock per run
Set in the Budget step. A cap pauses the run at the next experiment boundary; three misses in a row stop it.
