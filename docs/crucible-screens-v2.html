hooksiCommands run around each experiment. This is where database drift is solved — reset and reseed so experiment 3 sees the same data as experiment 1. Also where auth tokens get refreshed and logs captured.
before_each:
  - psql -f reset_and_seed.sql   # same data every experiment
  - curl -X POST /internal/cache/clear
  - ./scripts/refresh-token.sh    # token expires in 60 min
after_each:
  - docker logs payments-api --since 5m > logs/${experiment_id}.log
on_abort:
  - ./scripts/notify-team.sh
Hooks that fail block the experiment rather than being skipped. A reset that silently did nothing would make every later measurement wrong.

why results are not comparable across environmentsiDifferent hardware, different data volume, different neighbours. A campaign records which environment it ran in, and History refuses to diff two campaigns from different environments without warning you first.
A campaign records its environment on the manifest. Comparing a preprod-1 result against a local one is flagged, not silently allowed.

commanddoes
crucible plan -c "checkout latency"what it intends · changes nothing
crucible preflight -c "checkout latency"exercises target, restart and revert
crucible run -c "checkout latency"starts a campaign, streams to terminal
crucible run --tag smokeonly scenarios tagged smokeiTags let a twelve-scenario file be used three different ways without editing it. @smoke for a five-minute check, @peak for the full thing, @ceiling for probes.
crucible statuswhat is running, where, how far in
crucible approve <exp>approve a waiting proposal
crucible pausehold without discarding
crucible abortdiscard in-flight, revert to last committed
