01 · The Problem

Performance engineering is slow, expensive, and manual

When a service misses its SLA, an engineer must instrument it, run a load test, read metrics across tools with different units and update cadences, form a hypothesis, apply a change, re-test, and decide whether the improvement is real or noise. This loop takes hours even for an expert. It requires knowledge of at least three specialisms (load testing, observability, runtime internals) that are rarely combined in one person.

Commercial tools address slices of this. Akamas automates tuning but is optimisation-focused, not diagnosis-focused. Tricentis NeoLoad adds analysis to load testing but doesn't decide what to try next. Nothing closes the full loop.

Without Crucible
Manual load test → export CSV → open Grafana in another tab → form a guess → apply a change → wait for a restart → run another load test → compare numbers on paper. 2–4 hours. Requires 3 tool contexts held simultaneously.
With Crucible
Point Crucible at a service. It instruments, loads, diagnoses, proposes a change with a full evidence dossier, waits for approval, applies, re-tests, and delivers a verdict. Engineer reviews at approval gates only — the loop is hours, not days.

Metrics
Adapter breadth
Actuator (one instance, pinned), Prometheus/PromQL (service-wide histograms), Datadog (via micrometer-registry-datadog). Unit conversion + gauge peak sampling in the collector — the model never sees a raw Micrometer tuple.
Deploy
Sandbox-only writes
Crucible commits one file, pushes to perftest_sandbox only. Force-push refused always. Base branch (main) is read once, to create the sandbox on first use, and never written. Protected branch patterns refused at profile load time.
03 · Design Principles

Five rules that cannot be traded away

  • 1
    Nothing is claimed that was not measured.Verified and unverified experiments look different in the report. A prediction is a tracked signal, never a decision input.
  • 2
    The agent knows what it cannot see.Missing evidence is declared (available_evidence on every snapshot). "I looked and found nothing" is different from "I never looked."
  • 3
    The agent never grades itself.It cannot edit the SLA, the load profile, or the tests: all are protected paths in the guard. The SLA is locked a second time as a Policy memory record the agent has no write permission for.
  • 4
    A human holds every irreversible action.In Semi-Automated mode every change waits for the operator's approval, and the approval is bound: the exact diff approved is the exact diff deployed. Fully Automated is an operator's choice to pre-approve changes inside the profile's bounds; the guard and the measured verdict still decide.
  • 5
    Understanding is scored separately from outcome.The LUCKY quadrant — wrong diagnosis, fix worked anyway — is invisible to outcome-only scoring. An agent right by accident fails the next similar fixture.
04 · Key Capabilities

What Crucible actually does

Collect
Telemetry + unit conversion
Actuator, PromQL, Datadog. Micrometer timers converted from seconds to ms before the model sees them. Gauge peak sampled mid-run, never zero-padded. Unknown metrics declared, not dropped.
Diagnose
Evidence-based hypothesis
HikariCP saturation, GC pressure, thread exhaustion, slow queries, application code delays. Journal RAG filters disproven hypotheses. Cause family vocabulary per runtime profile.
Propose
Bounded config change
Property, new value, and allowed range from profile.yaml. A novel cause is permitted and recorded as novel — declared on the manifest, never silently normalised to a known family.
Verify
Measured verdict, not predicted
Applies the change, waits for the target to confirm the property is live (read-back from /actuator/env), runs a fresh measurement window. Verdict from observed p99, not from the model's estimate.
Guard
Allowlist command runner
Three layers: what it can run (no shell, an allowlist, inside the workspace, a timeout), what it can change (properties and bounds in profile.yaml), and what it can never write (the SLA as Policy memory). Protected paths cover the SLA, the profiles, the load script and the tests. Approved parameters are bound to the parked proposal. Every refusal is audited.
Score
Off-loop, model-free scorer
Reads manifests from disk. Six dimensions: outcome, diagnosis accuracy, integrity, efficiency, calibration, cost. Rescoring without re-running. LUCKY quadrant surfaced separately.
Four campaign modes
Three modes control how many human gates sit in the improvement loop — the underlying code path is identical, only the gate configuration differs. A fourth mode, Ceiling Probe, is a different kind of campaign entirely: it answers "how much headroom do I have?" rather than "what is broken?"
ModeGate at proposalGate at applyWho decides
AdvisoryFull stop — human reviews diagnosis + proposalHuman executesHuman leads, agent advises
Semi-AutomatedApprove / reject the diffAutomated after approvalHuman approves, agent executes
Fully AutomatedNone — bounded by policyAutomatedAgent decides within guardrail bounds
Ceiling ProbeN/A — no config changes madeN/A — load escalates, service is never modifiedOperator sets max load + step size; probe stops at first SLA miss
Ceiling Probe answers a different question: not "what is broken?" but "what can this service handle?" It escalates load in steps, holds each step long enough to measure (120 s warmup + 300 s measured, same as any experiment), and stops at the first step that misses the SLA. The result is a pair — last passing level and first failing level — with both measurements attached. It is deliberately started by an operator flag: because it changes the load profile, it is the one action the agent can never initiate on its own.

Fully Automated mode is inspired by the idea of an AI scientist that can propose experiments, run them unattended, and iterate on evidence — as Andrej Karpathy has described for LLM-driven research pipelines. Crucible applies this to performance engineering: every "experiment" is bounded by the property list in profile.yaml, every result is a manifest on disk, and the watchdog runs arithmetic checks every 5 minutes to decide whether to continue.
05 · Non-Functional Requirements

What the system must never compromise

CategoryRequirementHow enforced
Measurement integrity No measurement begins until the target proves the change is live Property read-back from /actuator/env; deploy timeout surfaces gap between "pushed" and "running"
Measurement integrity Gauges are sampled during load, not after Background sampler in collector; unsampled gauge is null, never 0
Measurement integrity Unit conversion before the model sees any value Collector converts Micrometer seconds → ms; every field name includes its unit
Safety The agent cannot widen its own authority Protected-path guard on the SLA, load profile, profiles and tests; the SLA also stored as Policy memory (operator-only write)
Safety No model output becomes a shell argument Allowlist command runner; refspec (remote + branch) is configuration, never model output
Safety Production targets refused Environment kind field; campaign refuses to start against production
Comparability Results across different models are flagged unreliable Every experiment records which model actually served it; report flags multi-model campaigns
Comparability Environment differences are flagged before comparison Campaign manifest records environment; diff command refuses cross-environment comparison
Reproducibility Every snapshot carries collector_version Eval runner refuses snapshots from a mismatched collector version; names which need recapture
Credential safety No secret appears in a model prompt or journal entry Allowlist redaction on all /actuator/env output before snapshot is written
Cost discipline Watchdog uses arithmetic, not model calls Seven tripwires checked every 5 min with no LLM; model fires only on ambiguous trip (≈2× per long scenario)
06 · Memory Taxonomy

Seven kinds of memory, each with a different lifetime and write authority

The choice of memory kind is a security decision as much as an engineering one. Policy memory gives the SLA its teeth — an agent that can overwrite its own objective is not safe to run autonomously.

Working
Current hypothesis and in-flight snapshot. Dies with the run.
Writer: runtime
Episode
Experiment manifests and the full campaign journal. Append-only, survives crashes.
Writer: runtime
Fact
"Gateway quota is 120 rps", "this app resets by truncate+reseed". Agent writes on confirmation. Designed, not built yet.
Writer: agent (confirmed)
Playbook
Cause signatures that worked. Service-scoped until a human promotes to global. Designed, not built yet: today the agent recalls earlier runs through the Journal RAG, and promotion is the next step.
Writer: agent, promoted by operator
Policy ⚠
The SLA, one record per campaign: endpoint, p99, error budget, noise floor. Agent has no write permission — ever. (The allowed properties and protected paths are operator-only too, but live in profile.yaml, guarded by path.)
Writer: operator only
Audit
Guard refusals, approvals, applies, reverts. Append-only, tamper-evident. Every human gate is recorded here.
Writer: append-only (system)
Document chunk
Architecture notes, runbooks, incident history. Embedded via Gemini embedding-001 at 768d, pinned per campaign.
Writer: indexer
Two RAGs, different purposes
Journal RAG — past manifests, queried at diagnosis so the agent doesn't re-propose a disproven hypothesis. Structured field filter first (fast, free), vectors only for narrative matching — dense retrieval is weak on exact identifiers like hikaricp.connections.pending.

Knowledge RAG — runbooks, architecture, incident notes, uploaded as .md or .txt. Today it feeds the Live AI chat (with citations), the wizard's AI suggestions and the S17 agent. Feeding it into campaign diagnosis, so the agent stops blaming the application for an API-gateway throttle, is the next step: not built yet.
07 · Benchmarks & Evaluation

A benchmark is five things, none optional

Task + harness + policy + scorer + manifest. A result produced without all five tells you nothing about the agent — it tells you about the gap you left open.
Replay vs Live split
Replay: diagnosis, refusal, confidence — ~2 s, $0.002. Run hundreds of times against captured fixtures.

Live: apply + restart + re-measure + verdict — ~15 min. Reserved for the full loop.

Fixtures captured once, properly: 120 s warmup discarded, 300 s measured. Every snapshot carries collector_version — a changed collector invalidates old fixtures, exactly as a changed embedder invalidates old vectors.
Six scoring dimensions
Outcome — verified fix, unverified fix, honest failure, false success or unreachable
Diagnosis accuracy — the 2×2: CORRECT, LUCKY, UNLUCKY, WRONG
Integrity — did it stay inside its authority (no metric-gaming change)?
Efficiency — how much of the experiment budget it spent
Calibration — predicted p99 against measured p99
Cost — priced from the manifest's own token counts

Scorer calls no model (crucible/perf/scorer.py). Reads manifests only. Rescore without re-running.
56 groups of reviewed test assertions · docs/CRUCIBLE_TEST_ASSERTIONS.md
Started as 34 assertions in 8 groups (measurement integrity, collector, guard, approval binding, deploy and verification, diagnosis, scorer, watchdog) and grew with every feature, through the dashboard contract tests of Group 53. Backed by 1993 passing pytest tests.

Benchmark of record (1 November 2026, gemini-3.5-flash-lite): live, 6 Fully Automated campaigns, 8 experiments — CORRECT 7, LUCKY 1, every SLA met, $0.0115. Replay, 23 clean snapshots, 40 cases — diagnosis correct on 31 of 37, task grade 32 of 40, $0.054.

Every assertion is reviewed by the operator before it is committed — Claude Code drafts the reasoning, the operator decides whether it matches the actual failure mode it is testing for.
08 · Under the Hood — Design Concepts

The ideas that make this work

Crucible featureUnderlying idea
Campaign loop structure Perception → Memory → Decision → Action. Collector is Perception; Journal RAG is Memory; Diagnosis is Decision; Applicator + Deploy is Action. Outcome earns the next piece of the graph — baseline must pass before experiments begin, diagnosis must pass before proposals are generated.
One collector, several providers Actuator, PromQL and Datadog adapters all feed the same collector, which converts units and declares what it could not read. A live campaign reads Actuator; fixture capture reads all three from one load window to check they agree. Choosing the provider for a live run is a planned setting (the Settings page previews it).
Journal RAG Dense vector retrieval is weak on exact tokens. Journals are full of identifiers like hikaricp.connections.pending — filter on structured fields first, use vectors only for narrative. Embedder is pinned per campaign; corpus embedded under one model is incompatible with another, exactly as a changed collector invalidates snapshots.
HITL approval gate A waiting step in the campaign loop. The proposal parks on disk with its exact parameters (~/.crucible/approvals/). An approval must carry those same parameters to be accepted — widening is structurally impossible, not a policy hope.
Guard enforced twice A single enforcement point can be bypassed if configuration moves. For the SLA, two independent mechanisms — protected path in the file guard and Policy memory kind — must both be weakened for a violation to succeed. Defence in depth, not defence by hope. (The load profile has the path lock only, for now.)
SKILL.md grants no authority Skills change how the model approaches work. They are rendered into the prompt and nowhere else — never into allowed_side_effects. A SKILL.md that says "you may raise pool size to 1000" has no effect; only the bounds in profile.yaml matter.
Scorer off-loop, no model An LLM judge costs ~7× the work it grades. More importantly, an agent that grades itself has every incentive to be generous. The scorer reads manifests from disk — deterministic, cheap, and structurally unable to be influenced by the agent it is scoring.
Credential redaction allowlist A blocklist that doesn't know a key name lets it through. An allowlist that doesn't know a key name blocks it. For secrets, the safe default is to redact the unknown, not pass it.
Watchdog arithmetic, not LLM 288 checks × $0.002 = $0.58 for a 24-hour scenario — more than the whole campaign budget. Arithmetic answers questions arithmetic can answer; a model call fires only when a tripwire trips ambiguously (≈2 times in a 24-hour run).
09 · Demo Flow

End-to-end walkthrough script

About 33 minutes, recorded with pauses while documents index and load windows measure. The demo runs one Semi-Automated campaign live; the other three modes are explained in words.

1
Problem, architecture and the target explain
Box A runs PerfLab (Spring Boot, Postgres, Redis, Prometheus) on Oracle Cloud; Box B runs Crucible and Locust; GLC v5 on Render is the model gateway. PerfLab has one endpoint per cause of slowness (/api/db pool exhaustion, /api/orders N+1 query, /api/churn GC pressure, …), so every diagnosis has a known right answer. /api/version reports the commit the running jar was built from.
2
Knowledge RAG: upload and index live
Upload PERF_LAB_PRODUCT.md. One background worker chunks it and embeds each chunk with gemini-embedding-001 at 768 dimensions into its own FAISS index. The embedder is pinned: changing it means re-indexing, never querying across two.
3
Grounded chat with citations live
Ask a question only the document answers. The reply cites the file it used; its SLA and profile facts are read from the YAML on disk.
4
Input data and request templates ui
Upload sizes.csv and map ${size} to its column for /api/orders?size=${size}. Every placeholder must map to an uploaded file and column before anything runs. Hooks (before_each, after_each, on_abort) are Python files run isolated, with an allowlisted environment.
5
Goal and SLA live
p99 ≤ 120 ms on /api/db. AI suggestion fills the form, bounds-checked. The 2.08% noise floor is read-only: measured on this box, and any change smaller than it is inconclusive.
6
Mode, scenarios, budget, review wizard
The four modes in words; Semi-Automated chosen. Budget foregrounds wall clock, not dollars, and caps pause rather than stop. Review shows the exact diff Launch writes — what crucible plan prints.
7
Guardrails: three layers ui
What it can run (no shell, allowlist, workspace, timeout); what it can change (profile.yaml properties and bounds — SKILL.md grants nothing); what it can never write (the SLA as Policy memory). Writes only to perftest_sandbox.
8
Preflight live
Read-only checks against the real target. With the apply probe it deploys a no-op change, reads it back, reverts and reads it back again — the steps every experiment runs.
crucible preflight --apply-probe
9
Live campaign and approval live
Baseline: the pool is 2 of 2 with requests queuing. The agent proposes a larger pool (2 → 50 in the 2 November trial); the operator approves that exact diff. Crucible commits one file, pushes, waits until the target reports the new commit (reading the value back too), then re-measures under identical load. Locust runs headless; the diagnosis reads server-side Actuator metrics.
crucible approve <run-id> --experiment 1 --as <you>
10
Results and the stores behind them live
Measured before and after, verdict against the noise floor, the prediction tracked apart from the result. Every result is a manifest file in results/; the Journal RAG reads those at diagnosis, the Knowledge RAG holds the documents.
11
Observability and CI/CD explain
Diagnosis reads Actuator today; PromQL and Datadog adapters exist, and choosing one for a live run is planned. Datadog, as PerfLab's own monitoring, saw the same run independently. Deploy is a push to the sandbox branch: a post-receive hook here, Jenkins or GitHub Actions elsewhere.
12
History and chat about runs live
The chat explains any run on disk by id, quotes measured values, calls a prediction a prediction, and says when a run does not exist. Unlike runs are flagged, not compared. A ceiling probe reports a pair, never a verdict.
13
Benchmarks and the LUCKY quadrant ui
Replay against stored snapshots versus live campaigns. Six scoring dimensions, no model call. Run 2: 7 CORRECT, 1 LUCKY — on the N+1 fault the agent first raised the pool, it helped by 11%, and the scorer marks it LUCKY because the pool was not the cause.
crucible bench --tasks config/tasks/ --fixtures fixtures/
14
Memory and the run's receipt live on Box B
Seven memory kinds, five live (Working, Episode, Policy, Audit, Document chunk); Fact and Playbook designed, not built. Open memory.sqlite and audit.jsonl, then read one manifest top to bottom: goal, baseline, change, approver, deployed commit and the commit the target reports, result, model.
15
CLI parity explain
Every button calls the same function as its command: same guard, same approval binding. Crucible runs headless from CI with no UI at all.
crucible plan | run | status | approve | resume | abort | report | diff | bench
